## 1. Мета — НЕ повний Shopify-embed, а мінімум для реальних скріншотів

Не будуємо зараз повноцінну Shopify-інтеграцію (OAuth, App Bridge,
Billing UI) — це окрема, більша задача поза фазовим планом. Мета вужча:
**один робочий екран у браузері**, який реально виконує заявлений
функціонал (prompt → превью → print-ready PDF), достатній для чесного
скріншоту/GIF у лістинг.

## 2. Що вже є (переюз, не дублювати)

- `server/prompt_to_brief`, `server/templater.brief_to_canvas`,
  `server/render`, `server/preflight_agent` — увесь бекенд-тракт готовий,
  викликається зараз лише з CLI.
- `server/schema.py` — канонічна CanvasJSON, яку клієнт мусить парсити
  ТОЧНО так само (інваріант CLAUDE.md §4, п.1: один JSON, ті самі `.ttf`).

**Чого немає й треба додати:** тонкий HTTP-шар над існуючими функціями —
CLI викликає їх напряму в процесі, браузеру потрібен API.

## 3. Скоуп

**Бекенд (мінімальний API, нова тонка обгортка, не новий pipeline):**
- `POST /api/brief` — `{prompt}` → `DesignBrief` (обгортка над
  `prompt_to_brief`).
- `POST /api/canvas` — `{brief}` → `CanvasJSON` (обгортка над
  `brief_to_canvas`).
- `POST /api/render` — `{canvas}` → PDF-файл (обгортка над `render` +
  `preflight_agent`, повертає готовий print-ready PDF або
  `needs_human`-звіт).
- `GET /api/preview/<id>` — растровий прев'ю-thumbnail (resvg, тільки для
  екрану — інваріант §4 п.2, друкарський файл лишається окремим).

**Клієнт (Fabric.js, одна сторінка):**
- Поле промпту → виклик `/api/brief` → `/api/canvas` → рендер прев'ю на
  Fabric.js canvas (з того самого CanvasJSON, тим самим шрифтом — інваріант
  §4 п.1, НЕ окремий рендер-шлях).
- Кнопка «Завантажити print-ready PDF» → `/api/render` → скачування.
- Мінімальний UI: без кастомізації позицій вручну (drag/resize) в MVP —
  це вже друга ітерація редактора, не потрібна для чесного скріншоту
  «prompt → готовий файл».

**Поза скоупом:** Shopify OAuth/App Bridge/Billing, ручне редагування
елементів на канвасі (drag/resize/color picker), збереження проєктів,
багатосторінковість.

## 4. Acceptance criteria

- [ ] Один прогін у браузері: ввести промпт → побачити прев'ю → скачати
      PDF, який проходить `preflight` з `status="ok"` на тому самому прикладі,
      що вже є в `examples/hello.json`-класі кейсів.
- [ ] Прев'ю на Fabric.js рендериться з ТОГО САМОГО CanvasJSON і шрифту,
      що йде на сервер — не окремий SVG/растровий шлях (інваріант §4 п.1).
- [ ] Скріншот цього екрану — реальний, не Figma-мокап.
