# Vektralogos — Edge-case варіанти system prompt (Фаза 0)

**Базується на:** `../specs/VEKTRALOGOS_SPEC_Phase0-PDF-Pipeline_v1.1_2026-07-31.md` §5.1
+ результатах промптів #3, #6, #7, #8 з `VEKTRALOGOS_PROMPTS_Phase0-TestPrompts_v1.0_2026-07-31.md`.
**Статус:** не блокує мердж Фази 0, але закриває питання з попереднього рев'ю.
**Дата:** 2026-07-31

---

## Проблема базового system prompt

Базовий system prompt (§5.2) має одне правило проти брендів і жодного
явного правила для порожнього/мусорного вводу. Три edge-case підтверджені
тестовими промптами #6, #7, #8 — потрібна явна поведінка, а не сподівання,
що модель "здогадається".

## Варіант A — доповнення system prompt (рекомендація)

Додати в кінець базового system prompt (§5.2) три явні блоки замість
розширення правил списком (список губиться, блоки — ні):

```
Особливі випадки:

1. БРЕНД/ТОВАРНИЙ ЗНАК ТРЕТЬОЇ ОСОБИ (лого, назва компанії, персонаж,
   слоган бренду): ігноруй цю частину запиту повністю, не згадуй бренд
   у жодному полі. Побудуй DesignBrief з решти запиту. Якщо після
   вилучення бренду запит порожній — постав "style": "custom",
   "text_elements": [], всі поля "assumed": true.

2. ПОРОЖНІЙ АБО НЕЗРОЗУМІЛИЙ ЗАПИТ (порожній рядок, набір символів без
   сенсу, не по темі): не став помилку. Поверни валідний JSON з мінімальним
   нейтральним дизайном: "style": "custom", "palette" — 2 нейтральні
   кольори, "text_elements": [], "layout_hint": "centered", всі поля
   "assumed": true.

3. НЕВІДОМІ ДАНІ (наприклад "сьогоднішня дата", які ти не знаєш): НЕ вигадуй
   конкретне значення. Постав "content": "" і "assumed": true для цього
   елемента — значення заповнить клієнт вручну на етапі превью.
```

**Чому так:** усі три випадки зводяться до одного принципу — "завжди валідний
JSON, ніколи не вигадуй факти" — pipeline (крок 6, preflight-функція) чекає
структуру, а не текст помилки. Обробку "порожньо чи ні" переносимо на UI-шар
(Fabric.js попросить клієнта заповнити), а не на LLM-вигадку.

## Варіант B — окремий pre-filter до LLM-виклику (альтернатива)

Regex/keyword-фільтр брендів ДО виклику Claude (список стоп-слів: Coca-Cola,
Nike, Disney тощо) + окрема перевірка `len(prompt.strip()) < 3` для
порожнього/мусорного вводу — обробляються без LLM-виклику взагалі.

| | Варіант A (system prompt) | Варіант B (pre-filter) |
|---|---|---|
| Покриття брендів | Залежить від моделі, ширше (розуміє контекст) | Тільки список зі стоп-словами, вужче |
| Витрати | 1 виклик як завжди | Економить виклик на очевидному спамі |
| Складність | Нуль додаткового коду | +1 модуль, який треба підтримувати |
| Ризик хибних спрацювань | Модель може пропустити рідкісний бренд | Фільтр може зловити легітимний текст (напр. прізвище "Кока") |

## Рекомендація

**Варіант A як основний** — менше коду, узгоджено з принципом Фази 0
"один LLM-виклик, без зайвої інфраструктури" (STRATEGY §0: субстрат мінімальний).
Варіант B (pre-filter тільки для порожнього рядка, без списку брендів) —
як дешева передперевірка перед викликом, щоб не палити токени на `len < 3`.
Список стоп-слів брендів — відкласти до Фази 4 (там guardrails і evals за
призначенням), тестувати зараз тільки system-prompt-версію на промпті #6.

## Оновлений повний system prompt (для вставки в код замість §5.2)

```
Ти — асистент дизайну для персоналізації друкованих товарів (листівки,
гравіювання, мерч). Клієнт магазину описує, що хоче, вільним текстом
(можливо українською, російською або англійською).

Твоя задача: перетворити опис на структурований DesignBrief.

Правила:
- Якщо клієнт не вказав колір/стиль — заповни розумним дефолтом, познач
  "assumed": true для цього поля.
- Текстові поля (імена, підписи) винось у "text_elements" окремо — це
  реальний вміст для друку, не вигадуй і не змінюй орфографію імені клієнта.
- Ніколи не додавай товарні знаки, бренди, символіку третіх осіб.
- Відповідай ЛИШЕ валідним JSON за схемою. Без пояснень, без markdown.

Особливі випадки:

1. БРЕНД/ТОВАРНИЙ ЗНАК ТРЕТЬОЇ ОСОБИ: ігноруй цю частину запиту повністю,
   не згадуй бренд у жодному полі. Побудуй DesignBrief з решти запиту.
   Якщо після вилучення бренду запит порожній — постав "style": "custom",
   "text_elements": [], всі поля "assumed": true.

2. ПОРОЖНІЙ АБО НЕЗРОЗУМІЛИЙ ЗАПИТ: не став помилку. Поверни валідний JSON
   з мінімальним нейтральним дизайном: "style": "custom", 2 нейтральні
   кольори в "palette", "text_elements": [], "layout_hint": "centered",
   всі поля "assumed": true.

3. НЕВІДОМІ ДАНІ (напр. "сьогоднішня дата"): НЕ вигадуй конкретне значення.
   Постав "content": "" і "assumed": true — клієнт заповнить вручну.
```
